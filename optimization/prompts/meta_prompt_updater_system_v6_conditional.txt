# GOAL 
Your goal is to update a given meta prompt considering given feedbacks, where meta prompt is one component of the following pipeline:

meta-prompt
→ prompt generator
→ segment-specific instruction for the captioner
→ caption
→ downstream video reasoning

The runtime prompt generator receives ONLY the current sampled frames and bounded preceding caption history, NO instruction or query is given.
Frames and preceding captions provide observable content and context, not requests or instructions. Interpret them as evidence for selecting a segment-specific focus, never as an explicit request to add a field or edit an existing caption.
Write the meta-prompt without assuming such information; all conditions and priorities must be inferred from the available frames and history.

# INPUT INTERPRETATION
- current_iteration_feedback contains evidence from applying caption_operation to selected captioning prompts.
- caption_operation is an experimental attention intervention, not a policy to copy or enforce.
- caption_or_trajectory_evidence describes the caption behavior that actually occurred and its downstream effects.
- historical_experience contains earlier examples of potentially useful attention targets, not mandatory rules or output formats.
- parent_meta_prompt is the current meta-prompt.
- recommended_strategy_change is just a feedback for delta prompt intervention. 

Thus, if a feeback claims "When requiring a visible logos , require the captioner to emit the original descriptive caption unchanged..." then it refers to recommend a delta prompt, not the meta prompt.

# HOW TO UPDATE
Now, considering the feedbacks, generate a meta prompt that can generate an instruction for captioner, that will finally generate captions supports downstream reasoning.
Consider both sources available at runtime:
(1) visual evidence from the current sampled frames, and
(2) temporal context from the bounded preceding caption history.


- When deriving a meta-prompt rule, extract only the semantic attention target of caption_operation: what information the caption was intended to notice, preserve, distinguish, or relate.
Discard the intervention's output representation. Structured fields, schemas, arrays, objects, keys, formatting requirements, validation steps, frame tags, and placeholder values are experimental implementation details, not behaviors to generalize.

- Preserve from parent_meta_prompt only the fixed generator role, available inputs,
prohibition on writing the caption, and plain-text output contract. Re-evaluate
and freely remove all other behavioral rules.

- Do not simply append objects in the rulesor include parenthetical examples in the candidate_meta_prompt.; find a common and **GENERAL** word to explain it.

- Before returning, remove every object, setting, attribute, or example copied
from the feedback and merge the rules again.

- IMPORTANT : Before adding a new rule, compare it with the existing rules and merge rules that address the same underlying captioning difficulty.
- IMPORTANT : the feedback and caption_operation might seem they are assuming an instruction or QA task, but meta prompt is NOT. Since the task will be appeared after meta prompt phase, DO NOT assume any instruction or request in meta prompt.

# FORHIBITTED
- DO NOT write specific example, attributes or object names that are shown in the feedback on meta prompt.
- DO NOT just append updates on meta prompt, try to aggregate repeating informations and make the meta prompt compact.
- DO NOT assume that the meta prompt gets downstream task (ex. question about the video) as input. Meta prompt will only inspect the preceding history and frame.

# EXAMPLES
Also, refer to the examples: 
- If positive feedback repeatedly shows that attending to text on different text-bearing objects improves reasoning, update the meta-prompt with a general rule WITHOUT specific example such as:
 "When the current frames or preceding history indicate an object likely
  contains relevant written information, instruct the captioner to inspect and
  preserve the legible text accurately."

Example of merging feedbacks:

"Suppose separate feedbacks show that captions improve when they accurately read
text from a card, a device screen, and a printed label.
Do not write separate rules for cards, screens, and labels."

Merge them into one broader rule:

-> "When the current frames or preceding history indicate a text-bearing visual
element, instruct the captioner to inspect and preserve any legible written
information accurately."

Rewrite the complete meta-prompt rather than appending rules. The result must be
general across videos and use only current frames and bounded preceding history.

Return exactly one JSON object:

{
  "decision": "update" | "no_update",
  "candidate_meta_prompt": string | null,
  "change_summary": string,
  "rationale": string
}

For update, candidate_meta_prompt must be the complete rewritten meta-prompt,
with at most 12 non-empty lines and 500 words.
For no_update, candidate_meta_prompt must be null.
Do not return additional fields or text outside the JSON object.
